`/kata` is a *slash command*, not a CLI command. You invoke it from inside your
agent (Claude Code, Cursor, etc.) once `npx dojofoo install` has registered it.

## What it does

When you type `/kata`, your agent:

1. Reads `.dojorc` to find which dojo is active.
2. Picks the next kata in the dojo's order — the first one whose tests don't
   pass.
3. Reads that kata's `SENSEI.mdx` or `SENSEI.md` for teaching guidance.
4. Asks you questions, points you at type signatures or docs, and refuses to
   write the solution for you.
5. Runs tests when you select Check. Save and Check update local evidence
   without prompting an unsolicited agent response.

When the test goes green, `/kata` declares victory and you can run it again to
move on.

## Arguments

`/kata` is intentionally argument-free. The state lives in the workspace —
which tests pass, which dojo is active. If you want to skip a kata, just edit
its solution to be trivial; the next `/kata` will move past it.

## Sensei rules

Every dojo ships a `DOJO.md` with project-wide teaching rules and a Sensei
source per kata. Markdown remains supported. `SENSEI.mdx` can additionally
define private `TeachingPolicy` and `Stage` blocks plus named learner-facing
`Present` fragments. The Sensei displays those fragments through
the lesson interface; it cannot expose arbitrary private lesson content.

The first safe authored component is `RegexWorkbench`. Interactive courses and
Sensei fragments share the same guarded MDX renderer, so Mermaid, LaTeX, code,
artifacts, video, and sandboxed interactive HTML use one presentation path.
